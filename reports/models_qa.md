ทุกชุดรันครบ **3 กลุ่มสินค้า × 5 ระยะพยากรณ์ (h = 2–6)** ทุกเดือนในช่วง validation (48 เดือน) และ test (86–90 เดือน) รวมค่าทำนาย **28,560 จุด**

### สิ่งที่ทุกโมเดลทำเหมือนกัน
- **ทาย:** y = % การเปลี่ยนแปลง (แบบ log) ของ IMI จากเดือน t ถึงเดือน t+h
- **วันที่ทาย:** วันที่ 15 ของเดือน t+2 และใช้เฉพาะข้อมูลที่เผยแพร่แล้ว ณ วันนั้น
- **แถวฝึก:** เฉพาะแถวที่คำตอบเผยแพร่แล้ว ณ วันทาย (เดือนฐาน ≤ t − h) ขยายหน้าต่างขึ้นเรื่อย ๆ (expanding window)
- **ฝึกใหม่ทุกเดือน** ทายครั้งละ 1 จุด แล้วเลื่อนไปเดือนถัดไป

## 1. No-change (ทายว่าราคาไม่เปลี่ยน)

**What: ทำอะไร?**
ทาย y = 0 ทุกครั้ง แปลว่า "เดือนเป้าหมายราคาเท่าเดือน t"

**Why: ทำไมต้องมีทั้งที่ดูโง่?**
เพราะราคามีค่าต่อเนื่องสูง การเดาว่าไม่เปลี่ยนมักถูกบ่อย (เหมือน "พรุ่งนี้อากาศเหมือนวันนี้") เป็น **ตัวเทียบที่สำคัญที่สุด** ถ้าโมเดลแพ้ตัวนี้ แปลว่าไม่มีประโยชน์

**Because: ใช้วัดอะไร?**
ใช้คำนวณ skill = 1 − MAE(โมเดล) ÷ MAE(No-change) เช่น นม h=3: MAE 2.20 เทียบ 2.54 → skill ≈ 13%

**ข้อสังเกต:** ไม่มีพารามิเตอร์ให้ปรับ ไม่ต้องฝึก

---

## 2. Historical mean (ค่าเฉลี่ยในอดีต)

**What: ทำอะไร?**
ทายว่า y = ค่าเฉลี่ยของ y ในข้อมูลฝึก ณ เดือนนั้น (เฉพาะแถวที่คำตอบออกแล้ว)

**Why: ทำไมมี?**
เป็นตัวเทียบที่บอกว่า "ถ้าราคามีแนวโน้มขึ้นเฉลี่ยเท่านี้อยู่แล้ว การทายค่าเฉลี่ยพอไหม" ต่างจาก No-change ตรงที่รวมแนวโน้มระยะยาว

**Because: เกี่ยวกับ Ridge อย่างไร?**
เมื่อ alpha ของ Ridge สูงมาก ผลของ Ridge จะเข้าใกล้ Historical mean (เห็นในกลุ่มเชื้อเพลิง ชุด 1, 2 และ 3-noRecent ที่ MAE เท่ากัน 9.61)

---

## 3. Seasonal naive (ตามปีก่อน)

**What: ทำอะไร?**
ทายว่าจะเปลี่ยนเท่ากับช่วงเดียวกันของปีที่แล้ว
y ทาย = 100 × [log IMI(t+h−12) − log IMI(t−12)]

**Why: ทำไมมี?**
ตรวจว่าราคามีฤดูกาลซ้ำทุกปีไหม (เช่น ปุ๋ยแพงก่อนฤดูปลูก)

**Because: ผลเป็นอย่างไร?**
แย่ที่สุดในทุกกลุ่ม (test h=3: ปุ๋ย 8.77, นม 3.54 เทียบ No-change 6.48 และ 2.54) แปลว่าราคาไม่ได้เปลี่ยนตามรูปแบบรายปีที่คงที่

**ข้อควรรู้:** ใช้ IMI ถึงเดือน t เท่านั้น (เพราะ h ≤ 12) จึงไม่มี leakage

## 4. ARIMA

**What: คืออะไร?**
โมเดลอนุกรมเวลาคลาสสิก ใช้ **ประวัติของ IMI ตัวเองอย่างเดียว** ไม่ใช้ค่าเงินหรือน้ำมัน ชื่อ ARIMA(p, d, q):
- **d = 1:** ใช้ผลต่างของ log IMI (การเปลี่ยนแปลง) เพราะดัชนีไม่นิ่ง
- **p:** ให้ค่าเปลี่ยนแปลงในอดีต p เดือนก่อนช่วยทาย (autoregressive)
- **q:** ให้ความคลาดเคลื่อนในอดีต q เดือนก่อนช่วยทาย (moving average)

**Why: ทำไมใช้ ARIMA?**
เป็นมาตรฐานของงานพยากรณ์อนุกรมเวลา ใช้ตอบว่า "ถ้าใช้แค่ประวัติ IMI ด้วยวิธีสถิติที่เหมาะสม จะทายได้แค่ไหน" ซึ่งต่างจาก Ridge ชุด 1 ที่ใช้ประวัติ IMI เหมือนกันแต่ผ่านสมการเส้นตรง

**How: เลือก order อย่างไร?**
ลองทุกคู่ p, q ∈ {0, 1, 2} และมี/ไม่มี drift (รวม 18 แบบ ต่อกลุ่ม) เลือกที่ AIC ต่ำสุด จากข้อมูล **ถึง ธ.ค. 2014 เท่านั้น** แล้วตรึงไว้

| กลุ่ม | order ที่เลือก | drift |
|---|---|---|
| เชื้อเพลิง (100) | ARIMA(1,1,0) | ไม่มี |
| ปุ๋ย (318) | ARIMA(1,1,2) | ไม่มี |
| นม (402) | ARIMA(2,1,2) | ไม่มี |

**How: ใช้ทายอย่างไร?**
ทุกเดือน fit ค่าสัมประสิทธิ์ใหม่ด้วย log IMI ถึงเดือน t แล้วพยากรณ์ล่วงหน้า h ขั้น (1 ครั้งต่อกลุ่ม ต่อเดือน ใช้กับทุก h)

**What: AIC คืออะไร?**
ตัวเลขที่ชั่งระหว่างความพอดีกับความซับซ้อนของโมเดล ยิ่งต่ำยิ่งดี ใช้กัน overfit

**Because: ผลเป็นอย่างไร?**
สำหรับนม ARIMA เป็นโมเดลที่ดีที่สุดจาก validation ที่ h=2, 4, 5, 6 และใน test ได้ MAE 2.07 ที่ h=3 เทียบ No-change 2.54 แปลว่าความแม่นของนมมาจากประวัติราคาเอง

## 5. Ridge Regression (โมเดลหลัก)

**What: คืออะไร?**
สมการเส้นตรง: ค่าทาย = ค่าคงที่ + (น้ำหนัก₁ × feature₁) + (น้ำหนัก₂ × feature₂) + … โดยมี **ตัวลงโทษ (alpha)** กันไม่ให้น้ำหนักตัวใดใหญ่เกินไป

**Why: ทำไมเลือก Ridge เป็นโมเดลหลัก?**
- ข้อมูลมีแค่ราว 200–300 แถวต่อกลุ่ม โมเดลซับซ้อนจะ overfit
- feature หลายตัวสัมพันธ์กันเอง (เช่น การเปลี่ยนแปลง 1, 2, 3 เดือนของตัวเดียวกัน) Ridge เสถียรกับเรื่องนี้
- อธิบายได้ผ่านน้ำหนักของ feature ซึ่งแสดงใน dashboard ได้

**How: ฝึกอย่างไร?**
1. ปรับ feature ให้มีค่าเฉลี่ย 0 ส่วนเบี่ยงเบน 1 (standardize) โดยคำนวณจาก **ข้อมูลฝึกของเดือนนั้นเท่านั้น**
2. ฝึก Ridge ด้วย alpha ที่เลือกไว้
3. ทาย 1 จุด

**Why: ทำไมต้อง standardize?**
เพราะ Ridge ลงโทษน้ำหนักตามขนาด ถ้า feature มีหน่วยต่างกัน (เช่น ความผันผวนของน้ำมันกับ % เปลี่ยนค่าเงิน) feature ที่ตัวเลขใหญ่จะถูกลงโทษไม่เท่ากัน

**How: เลือก alpha อย่างไร?**
- ลอง 15 ค่า (0.01 ถึง 100,000 แบบ log scale)
- ใช้ช่วง validation (48 เดือน) หา alpha ที่ MAE ต่ำสุด แยกตามกลุ่ม ระยะ และชุด feature (รวม 75 ชุด)
- ถ้าเท่ากันเลือก alpha ที่ใหญ่กว่า
- **ตรึง alpha นั้นไว้ตลอดช่วง test** (น้ำหนักยังฝึกใหม่ทุกเดือน)

**What: alpha สูง/ต่ำหมายถึงอะไร?**
- alpha สูง: เบรกแรง โมเดลระมัดระวัง ทายใกล้ค่าเฉลี่ย
- alpha ต่ำ: เบรกเบา เชื่อ feature เต็มที่
- ตัวอย่าง: ปุ๋ย h=3 ชุด 3 ใช้ alpha 100 · นม h=3 ชุด 3-cutoff24 ใช้ alpha 1,000 (เบรกแรง ทำให้ค่าทายของนมไม่เกินราว 2.1%)

**Because: ทำไมขยาย grid alpha?**
รอบแรกใช้ 0.01–1,000 แล้วค่าที่เลือกชนขอบบน 31 จาก 75 ชุด จึงขยายเป็น 100,000 เหลือชนขอบ 9 ชุด ซึ่งเป็นกลุ่มเชื้อเพลิงที่ feature ไม่ช่วยจนผลเท่ากับ Historical mean ตัดสินจาก validation เท่านั้น

**What: Ridge รันกับ feature อะไรบ้าง?**

| ชุด | มีอะไร | ตอบ |
|---|---|---|
| 1 | ประวัติ IMI 6 ตัว | ตัวเทียบ |
| 2 | + ค่าเงิน (11 ตัว) | ค่าเงินช่วยไหม |
| 3 | + ค่าเงิน + น้ำมัน (16 ตัว) | ข้อมูลภายนอกช่วยไหม |
| 3-noRecent | ชุด 3 ไม่มีข้อมูลเดือน t+1 (14) | ช่วยเพราะรู้ก่อนไหม |
| 3-cutoff24 | ชุด 3 ใช้ t+1 แค่วันที่ 1–24 (16) | ความไว |

**What: Ridge ให้น้ำหนัก feature อะไรมาก?**
ในโมเดลปุ๋ย h=3 (ชุด 3) feature ที่น้ำหนักสูงสุดคือ การเปลี่ยนแปลงของราคาน้ำมันเดือน t+1 (`brent_lead_t1_full_pct`) รองลงมาคือการเปลี่ยนแปลง IMI 1 เดือนและความผันผวนของค่าเงิน (ดูได้ใน dashboard ส่วน "รายละเอียดทางเทคนิค")

**Because: ผลของ Ridge เป็นอย่างไร?**
- Test h=3: ปุ๋ย ชุด 3 MAE 6.37 (ดีที่สุดในกลุ่ม) · นม ชุด 1 MAE 2.06 (ดีที่สุด)
- ชุด 3 เทียบชุด 1: ปุ๋ยดีขึ้น 0.4% · นมแย่ลง 7.0% · ไม่มีนัยสำคัญ

## 6. XGBoost

**What: คืออะไร?**
ต้นไม้ตัดสินใจหลายต้นต่อกัน แต่ละต้นแก้ความผิดพลาดของต้นก่อนหน้า เช่น "ถ้าน้ำมันขึ้นเกิน X% และ IMI เดือนก่อนขึ้น → ทายว่าขึ้น Y"

**Why: ทำไมใช้?**
เพื่อเทียบว่าโมเดลที่จับความสัมพันธ์ซับซ้อน (ไม่ใช่เส้นตรง) ได้ จะดีกว่า Ridge ไหม เป็นโมเดล ML ที่นิยมกับข้อมูลตาราง

**How: ตั้งค่าอย่างไร?**

| พารามิเตอร์ | ค่า | เหตุผล |
|---|---|---|
| จำนวนต้นไม้ | 200 | ตาม Scope |
| ความลึกต้นไม้ | 2 | ค่าต่ำสุดของช่วงที่กำหนด (2–3) เพราะข้อมูลน้อย |
| learning rate | 0.05 | เรียนรู้ช้า ๆ กัน overfit |
| random_state | 0 | ให้ผลเท่าเดิมทุกครั้ง |

**ไม่ได้จูนพารามิเตอร์** และฝึกใหม่ทุกเดือนเหมือนโมเดลอื่น (รวมประมาณ 10,200 ครั้งต่อการรัน)

**Why: ทำไมไม่จูนให้ดีขึ้น?**
เพราะข้อมูลน้อย การจูนจะ overfit กับ validation และเรากำหนดให้ความสำคัญกับการจัดเวลาและการประเมินที่ถูกต้องมากกว่าการเพิ่มความซับซ้อน

**Because: ผลเป็นอย่างไร?**
แพ้ Ridge ในแทบทุกกลุ่มและชุด (ปุ๋ย h=3: XGBoost ชุด 3 MAE 6.44 เทียบ Ridge 6.37; นม: XGBoost 2.21 เทียบ Ridge 2.20) เพราะข้อมูล 200–300 แถวน้อยเกินไป โมเดลจึงจำข้อมูลเก่ามากกว่าเรียนรู้รูปแบบ (overfit) ซึ่งเราคาดไว้ก่อนทดลอง ยกเว้นเชื้อเพลิงที่ XGBoost ชุด 3 ได้ MAE ต่ำสุดใน test (9.24)

## ใครถูกเลือกเป็น "โมเดลที่ดีที่สุด" ในแต่ละกลุ่ม

เลือกจาก MAE ช่วง **validation** ต่ำสุด (ไม่นับ No-change เพราะเป็นตัวเทียบ) ไม่ใช่จาก test:

| กลุ่ม | h=2 | h=3 | h=4 | h=5 | h=6 |
|---|---|---|---|---|---|
| เชื้อเพลิง (100) | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 |
| ปุ๋ย (318) | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 | Ridge ชุด 3 |
| นม (402) | ARIMA | Ridge ชุด 3-cutoff24 | ARIMA | ARIMA | ARIMA |

**ข้อสังเกต:**
- ปุ๋ยและเชื้อเพลิงเลือก Ridge ชุด 3 (ใช้ข้อมูลภายนอก) ทุกระยะ
- นมส่วนใหญ่เลือก ARIMA (ใช้ประวัติราคาอย่างเดียว)
- ใน test นมที่ h=3 โมเดลที่เลือก (Ridge ชุด 3-cutoff24) MAE 2.20 ซึ่งแย่กว่า Ridge ชุด 1 (2.06) เล็กน้อย เพราะ validation กับ test ให้ผลไม่ตรงกัน เราไม่เปลี่ยนโมเดลหลังเห็นผล test

## คำถามที่อาจารย์น่าจะถามเรื่องโมเดล

**ถาม: ทำไมใช้โมเดลเส้นตรงทั้งที่ราคาไม่เป็นเส้นตรง?**
เพราะข้อมูลน้อย โมเดลไม่เป็นเส้นตรง (XGBoost) แพ้ Ridge ใน test เรายังลองแล้วเปรียบเทียบจริง ไม่ได้สมมติว่าเส้นตรงดีกว่า

**ถาม: ทำไมไม่ใช้โมเดลที่ซับซ้อนกว่านี้ เช่น LSTM?**
ข้อมูลราว 300 เดือนต่อกลุ่มน้อยเกินไปสำหรับโครงข่ายประสาทเทียม ซึ่งต้องการข้อมูลมาก และ XGBoost ที่ซับซ้อนกว่า Ridge ก็ยังแพ้อยู่แล้ว

**ถาม: ทำไม baseline มีหลายตัว?**
แต่ละตัวตอบคำถามต่างกัน: No-change = ไม่มีข้อมูลเลย · ค่าเฉลี่ย = มีแค่แนวโน้มยาว · Seasonal naive = มีแค่ฤดูกาล · ARIMA = ใช้ประวัติด้วยวิธีสถิติเต็มรูปแบบ ถ้าโมเดลเราชนะทุกตัวจึงจะน่าเชื่อ

**ถาม: ทำไม ARIMA ไม่ใช้ค่าเงินหรือน้ำมัน (ไม่ทำ ARIMAX)?**
เพราะต้องการให้ ARIMA เป็นตัวแทนของ "การใช้ประวัติ IMI อย่างเดียว" เพื่อเทียบกับโมเดลที่ใช้ข้อมูลภายนอก (Ridge)

**ถาม: ทำไมเลือก alpha จาก validation ไม่ใช้ cross-validation?**
เพราะเป็นอนุกรมเวลา ถ้าทำ cross-validation แบบสุ่มจะเห็นข้อมูลอนาคต ใช้ช่วง validation ที่อยู่ก่อน test ตามเวลา ซึ่งตรงกับการใช้งานจริง

**ถาม: โมเดลหลายตัวขนาดนี้ ไม่เสี่ยง "เลือกตัวที่ดูดี" หรือ?**
เสี่ยง จึงกำหนดไว้ก่อนว่า (1) เลือกโมเดลที่ดีที่สุดจาก validation ไม่ใช่ test (2) เปรียบเทียบหลักแค่ 3 ข้อ (3) ปรับ p-value ด้วย Holm สำหรับ 6 การทดสอบ ผลนอกจากนี้ถือเป็นเชิงสำรวจ

**ถาม: ทำไมนมที่ดีที่สุดใน validation (ARIMA/Ridge ชุด 3-cutoff24) ไม่ใช่ตัวที่ดีที่สุดใน test (Ridge ชุด 1)?**
validation มีแค่ 48 เดือน ความต่างระหว่างโมเดลเล็กน้อย (Ridge ชุดต่าง ๆ ของนมมี MAE ใกล้กันมากที่ 1.14–1.16) ลำดับจึงสลับกันได้ง่าย เราไม่แก้หลังเห็น test

**ถาม: โมเดลที่ใช้ใน dashboard คืออะไร?**
ใช้โมเดลที่เลือกจาก validation ตามตารางข้างต้น ฝึกใหม่ ณ วันพยากรณ์ล่าสุด (15 ก.ย. 2569) และตรวจแล้วว่าค่าที่คำนวณซ้ำของเดือนสุดท้ายในช่วง test เท่ากับขั้น Modeling ทุกระยะ

**ถาม: ผลของ Ridge ตีความได้ไหม?**
ได้ระดับหนึ่ง น้ำหนักบอกว่า feature ไหนผลักค่าทายขึ้นหรือลง แต่ feature สัมพันธ์กันเอง และน้ำหนักเปลี่ยนทุกเดือนที่ฝึกใหม่ จึงตีความเป็นภาพรวมได้ ไม่ใช่เหตุและผล
