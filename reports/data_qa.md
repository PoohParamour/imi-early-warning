## หมวด 1: ที่มาของข้อมูล

**What: ใช้ข้อมูลอะไรบ้าง?**
3 กลุ่ม: (1) ข้อมูลหลัก IMI ของ สนค. (2) ข้อมูลภายนอก คือค่าเงินและราคาน้ำมันจาก FRED (3) ข้อมูลเสริม ได้แก่ CPI/PPI ของ สนค. สำหรับวัดราคาในประเทศ ปฏิทินวันเผยแพร่ IMI และราคาปุ๋ยกับนมโลกสำหรับรอบที่ 2

**Because: ข้อมูลเป็น Open Data จริงไหม มีหลักฐานอะไร?**
- IMI อยู่บน data.go.th (ชุดข้อมูล `tpso_data_70`) ใบอนุญาต Open Data Common
- CPI อยู่บน GD Catalog ใบอนุญาต Open Data Common
- FRED เป็น Public Domain (ขออ้างอิง) และ World Bank Pink Sheet เป็น CC BY 4.0
- ทุกแหล่งดาวน์โหลดได้ฟรี ไม่ต้องใช้ API key และบันทึก URL จริงไว้ใน `sources.json`

**Why: ทำไมใช้ข้อมูลจาก FRED ไม่ใช้ของ ธปท.?**
API ของ ธปท. ต้องลงทะเบียนและรออนุมัติ เราใช้ข้อมูล Federal Reserve ซึ่งอ้างอิงได้ และ feature เป็น % การเปลี่ยนแปลง ความต่างจากอัตราอ้างอิงในไทยจึงน่าจะน้อย (ยังไม่ได้วัด เขียนเป็นข้อจำกัด)

**What: ดึงข้อมูลอย่างไร?**
- IMI: ส่งคำขอ POST ทีละเดือน 320 ครั้ง (1 คำขอ = 1 เดือน ใส่ 81 รหัส) ไม่มีคำขอล้มเหลว
- FRED: ดาวน์โหลดไฟล์ CSV ด้วย `curl` เพราะ Python `requests` เกิด timeout ซ้ำ ขณะที่ `curl` ดาวน์โหลด URL เดียวกันสำเร็จ
- ทุกไฟล์ตั้งชื่อด้วย timestamp UTC กันเขียนทับ

**Why: ทำไมต้องเก็บ request manifest ด้วย?**
เพื่อตรวจย้อนกลับได้ว่าส่งคำขออะไรไปบ้าง (เดือน รหัส จำนวนแถวที่ได้) ไฟล์ `imi_request_manifest` มี 320 รายการ ตรงกับ 320 เดือน

**What: `sources.json` มีอะไร ทำไมสำคัญ?**
ทะเบียนของทุกไฟล์: ชื่อแหล่ง เจ้าของ URL วิธีเรียก เวลาดาวน์โหลด จำนวนแถว ช่วงข้อมูล ชื่อไฟล์ SHA-256 ใบอนุญาต ข้อความอ้างอิง สำคัญเพราะใช้พิสูจน์ได้ว่าข้อมูลมาจากไหนและไม่ถูกแก้

**Because: SHA-256 ใช้ทำอะไร?**
เป็น "ลายนิ้วมือ" ของไฟล์ ถ้าแก้ไฟล์แม้ 1 ตัวอักษร ค่าจะเปลี่ยน ทุก notebook เทียบ SHA-256 ก่อนใช้ไฟล์ ถ้าไม่ตรงจะหยุดทันที

**What: ข้อมูลอ้างอิงอย่างไร?**
มีข้อความอ้างอิงในแต่ละรายการของ `sources.json` และรวมในรายงานหัวข้อเอกสารอ้างอิง

## หมวด 2: ไฟล์แต่ละไฟล์ใน `data/raw/`

**What: `imi_monthly_...csv` คืออะไร?**
ดัชนีราคานำเข้ารายเดือน 81 รหัสสินค้า × 320 เดือน = 25,752 แถว ไม่มีค่าว่างและไม่มีแถวซ้ำ ทุกรหัสที่ใช้มีครบ 320 เดือน

**What: คอลัมน์สำคัญของไฟล์ IMI มีอะไร?**
- `commodityCode`, `commodityNameTH` รหัสและชื่อกลุ่ม
- `year` (พ.ศ.), `month`
- `index` ค่าดัชนี (ตัวที่เราใช้)
- `change` % เทียบเดือนก่อน, `changeYear` % เทียบปีก่อน
- `yearBase` ปีฐาน = 2555
- `createdAt` วันที่ API สร้างข้อมูล

**Because: ทำไม `createdAt` สำคัญ?**
ทุกแถวมีค่าเดียวกัน (2026-09-28) แปลว่า API สร้างข้อมูลใหม่ทั้งชุด เราจึงตรวจประวัติการแก้ไขข้อมูลย้อนหลังไม่ได้ ถ้าเคยแก้ จะเกิด leakage เล็กน้อยที่เรามองไม่เห็น เขียนไว้เป็นข้อจำกัด

**What: รหัสที่ใช้ในงานคืออะไร?**
`318` ปุ๋ยและยากำจัดศัตรูพืช · `402` นมและผลิตภัณฑ์นม · `100` เชื้อเพลิง (ตรวจ pipeline) · `000` รวมทุกรายการ ที่เหลืออีก 77 รหัสเก็บเป็นข้อมูลดิบแต่ไม่ได้ใช้

**What: `imi_master_...json` คืออะไร?**
รายชื่อรหัสและช่วงข้อมูลที่ API แจ้ง (IMI 81 รหัส, EXI 83 รหัส) ใช้กำหนดว่าต้องดึงเดือนไหนบ้าง จึงไม่ต้องใส่ตัวเลขช่วงเวลาเองในโค้ด

**What: ปฏิทินเผยแพร่ IMI คืออะไร ทำไมต้องมี?**
ไฟล์ 21 แถวที่ไล่เก็บจากข่าวของ สนค. ว่าแต่ละเดือนข้อมูลออกวันไหน (พ.ย. 2024 – ก.ค. 2026) ช้ากว่าสิ้นเดือน 26–41 วัน ใช้กำหนดวันพยากรณ์เป็นวันที่ 15 ของเดือน t+2 เพราะทุกเดือนออกไม่เกินวันที่ 10 ของ t+2

**Why: ทำไมต้องไล่ดูข่าวเอง ไม่ใช้วันที่จากข้อมูล?**
เพราะข้อมูลที่ API ให้มีแต่วันที่สร้างข้อมูลใหม่ (`createdAt`) ซึ่งไม่ใช่วันที่เผยแพร่ครั้งแรก

**What: ข้อมูลค่าเงินกับน้ำมันเป็นอย่างไร?**
รายวัน ค่าเงินเริ่มปี 1981 น้ำมันเริ่มปี 1987 มีค่าว่างในวันหยุดตลาด (ค่าเงิน 536 วัน น้ำมัน 1,173 วัน) เราใช้เฉพาะตั้งแต่ปี 2000

**Why: ทำไมดึงข้อมูลย้อนไปถึงปี 1981 ทั้งที่ใช้ตั้งแต่ปี 2000?**
เพราะดาวน์โหลดทั้งไฟล์ได้ในคำขอเดียวและเก็บเป็นข้อมูลดิบครบ ส่วนการเลือกช่วงทำในขั้นเตรียมข้อมูล

**What: ไฟล์ CPI และ PPI คืออะไร ใช้ทำอะไร?**
- CPI: ดัชนีราคาผู้บริโภคหมวดนมและผลิตภัณฑ์นม (รหัส 11320, 297 เดือน)
- PPI: ดัชนีราคาผู้ผลิต 2 รหัส (3105 ผลิตภัณฑ์นม, 3201 เคมีภัณฑ์ขั้นมูลฐาน ปุ๋ยเคมี พลาสติก) 140 เดือนต่อรหัส
- ใช้วัดว่าราคาในประเทศตามหลังราคานำเข้ากี่เดือน ไม่ใช้เป็น feature หรือ target

**Because: ทำไม CPI ดึง 320 คำขอแต่ได้ 297 แถว?**
เพราะ API มีข้อมูลหมวดนี้ตั้งแต่ ธ.ค. 2001 คำขอ 23 ครั้งแรกจึงได้ผลว่าง ไฟล์เก็บเฉพาะที่มีข้อมูล

**What: ไฟล์ Pink Sheet และ FAO คืออะไร?**
สำหรับรอบที่ 2: Pink Sheet (Excel) มีราคายูเรียและ DAP รายเดือน ดอลลาร์ต่อตัน ส่วน FAO (CSV) มีดัชนีราคานมโลก (Dairy, 2014–2016 = 100) ทั้งสองมีข้อมูลถึง ก.ย. 2026

**Because: เปิดไฟล์ Pink Sheet และ FAO ต้องระวังอะไร?**
- Pink Sheet มีหัวตารางหลายบรรทัด ข้อมูลเริ่มบรรทัดที่ 7 เดือนเขียนเป็น `2026M09` และชื่อคอลัมน์ `Urea` มีช่องว่างท้ายชื่อ
- FAO มีบรรทัดอธิบาย 3 บรรทัดก่อนหัวตาราง

**What: ข้อมูลภายนอกอื่นที่ใช้มีใบอนุญาตอะไร?**
FRED: Public Domain (ขออ้างอิง) · World Bank: CC BY 4.0 · FAO: ตาม FAO Terms [ยังไม่ยืนยันรายละเอียด] · ปฏิทินเผยแพร่และ PPI: [ยังไม่ยืนยันหน้าชุดข้อมูล]

## หมวด 3: คุณภาพข้อมูล

**What: ตรวจคุณภาพข้อมูลอย่างไร?**
ตรวจ schema (คอลัมน์ครบ) · ค่าซ้ำ (ไม่มี) · ค่าว่าง (IMI ไม่มี) · ความต่อเนื่องของทุกเดือนต่อรหัส · ค่าดัชนีต้องเป็นบวก (เพราะใช้ log) · และ SHA-256 ของทุกไฟล์

**Because: ข้อมูลครบทุกเดือนจริงไหม?**
กลุ่ม 100, 318, 402 และ 000 มีครบ 320 เดือนทุกกลุ่ม (assert ใน notebook 01) ส่วนรหัสอื่น 3 รหัส (315, 401, 417) หยุดเผยแพร่กลางทาง แต่ไม่ใช่กลุ่มที่ใช้

**What: ข้อมูลรายวันมีปัญหาอะไร?**
- มีค่าว่างในวันหยุด
- ในแต่ละเดือน ค่าเงินมีข้อมูลทั้งเดือนต่ำสุด 18 วัน น้ำมันต่ำสุด 9 วัน (มัธยฐานทั้งสองอยู่ที่ 21 วัน)

**Why: ทำไมไม่เติมค่าศูนย์ในวันหยุด?**
เพราะศูนย์จะดึงค่าเฉลี่ยต่ำผิดความจริง ราคาน้ำมัน 0 ดอลลาร์ไม่มีอยู่จริง เราเฉลี่ยเฉพาะวันที่มีข้อมูล

**What: น้ำมันมีเดือนที่ข้อมูลน้อยผิดปกติไหม?**
มี 3 เดือน: ธ.ค. 2000, พ.ย. 2002, มี.ค. 2006 (มีข้อมูลทั้งเดือน 10, 10 และ 9 วัน) วันที่ขาดเป็นวันทำการ และส่วนใหญ่ค่าเงินในวันเดียวกันมีค่า จึงเป็นช่องว่างของข้อมูลต้นทาง สาเหตุเชิงลึกยังไม่ยืนยัน

**Because: เดือนเหล่านั้นกระทบผลไหม?**
ไม่ เพราะกระทบเฉพาะแถวที่เดือนฐาน t ไม่เกิน ก.ย. 2006 ซึ่งอยู่ในช่วงฝึก ไม่กระทบ validation และ test

**Why: ทำไมไม่เติมค่าหรือตัดเดือนเหล่านั้นทิ้ง?**
เพราะเฉลี่ยจากวันที่มีก็ยังใช้ได้ และไม่กระทบช่วงที่ใช้วัดผล การเติมค่าจะเป็นการสร้างข้อมูลที่ไม่มีจริง

**What: ข้อมูลมี outlier ไหม จัดการอย่างไร?**
มีการเปลี่ยนแปลงแรง เช่น ปุ๋ยพุ่งราว 32% ต้นปี 2026 เป็นเหตุการณ์จริงของตลาด ไม่ใช่ข้อผิดพลาดของข้อมูล เราไม่ตัดทิ้ง เพราะจะทำให้ผลดูดีเกินจริง

**What: ข้อมูลมีความเอนเอียง (bias) หรือข้อมูลส่วนบุคคลไหม?**
- ไม่มีข้อมูลส่วนบุคคล เป็นดัชนีรวมระดับกลุ่มสินค้าและราคาตลาดรายวัน
- ความเอนเอียงที่ต้องรู้: IMI สะท้อนราคาเฉลี่ยของทั้งกลุ่ม ไม่ใช่ราคาของผู้ซื้อแต่ละราย และสรุปแทนสินค้ากลุ่มอื่นไม่ได้

5 ขั้น: (1) แปลงปี พ.ศ. เป็น ค.ศ. (2) เฉลี่ยข้อมูลรายวันเป็นรายเดือน 2 แบบ คือทั้งเดือนและเฉพาะวันที่ 1–24 (3) สร้างคำตอบ y (4) สร้าง feature จากข้อมูลที่เผยแพร่แล้ว ณ วันพยากรณ์ (5) ตรวจ 8 เงื่อนไขทุกแถว

**Why: ทำไมไม่แก้ไฟล์ใน `raw/` โดยตรง?**
เพื่อให้ตรวจย้อนกลับได้ ทุกการแปลงทำในโค้ด notebook และเขียนผลไปไฟล์ใหม่ ถ้ารันซ้ำก็ได้ผลเดิม

ค่าเฉลี่ยรายเดือนของค่าเงินและน้ำมัน 642 แถว (2 series × 321 เดือน) มีทั้งแบบเต็มเดือน (`full_mean`) แบบวันที่ 1–24 (`cutoff24_mean`) จำนวนวัน (`full_n`) และวันที่ล่าสุดที่ใช้ (`full_max_date`) ใช้ตรวจว่าข้อมูลที่ใช้ไม่เกินวันพยากรณ์

ตารางที่ใช้สร้างโมเดล 4,560 แถว 32 คอลัมน์ 1 แถว = 1 กลุ่ม × 1 เดือนฐาน t × 1 ระยะ h ต่อกลุ่ม: h=2 มี 306 แถว h=3 มี 305 h=4 มี 304 h=5 มี 303 h=6 มี 302

**What: คอลัมน์ในตารางนี้แบ่งเป็นกลุ่มอะไร?**

- feature ประวัติ IMI: การเปลี่ยนแปลง 1, 2, 3, 6, 12 เดือน และความผันผวน
- feature ค่าเงิน/น้ำมัน: การเปลี่ยนแปลง 1–3 เดือน ความผันผวน และค่าของเดือน t+1
- คอลัมน์ `*_max_date`: ใช้ตรวจ leakage

**What: คำตอบ (target) คำนวณอย่างไร?**
y = 100 × [log(IMI เดือนเป้าหมาย) − log(IMI เดือน t)] หน่วยเป็นจุดร้อยละ

**Because: ทำไมแต่ละ h มีจำนวนแถวไม่เท่ากัน?**
เพราะ h ยิ่งยาว เดือนเป้าหมายยิ่งไกล เดือนฐานล่าสุดที่มีคำตอบจึงถอยหลังไป (h=2 ถึง มิ.ย. 2026, h=6 ถึง ก.พ. 2026)

**Because: ตารางมีค่าว่างไหม?**
ไม่มีในคอลัมน์ feature และคำตอบ (ตรวจแล้ว 0 เซลล์) เพราะแถวที่ feature หรือคำตอบไม่ครบถูกตัดออกตั้งแต่ตอนสร้างตาราง

**What: `processed/latest_features.csv` คืออะไร?**
9 แถว = 3 กลุ่ม × 3 เดือนฐานล่าสุด (มิ.ย., ก.ค., ส.ค. 2026) ที่ยังไม่มีคำตอบ ใช้พยากรณ์จริงใน dashboard

## หมวด 5: การกันข้อมูลรั่ว (leakage) ที่เกี่ยวกับข้อมูล

**What: feature แต่ละตัวใช้ข้อมูลถึงวันไหน?**
- feature ประวัติ IMI และ feature ถึงเดือน t: ใช้ข้อมูลถึงเดือน t
- feature ของเดือน t+1 (ค่าเงินและน้ำมัน): ใช้ข้อมูลทั้งเดือน t+1 ซึ่งจบก่อนวันพยากรณ์ (วันที่ 15 ของ t+2)

**Because: ตรวจอย่างไรว่าข้อมูลของเดือน t+1 ไม่เกินวันพยากรณ์?**
เก็บวันที่ observation ล่าสุดที่ใช้ไว้ในคอลัมน์ `*_max_date` แล้วตรวจทุกแถวว่าอยู่ก่อน `forecast_origin` ผ่าน 0 violation จาก 8 เงื่อนไข

**Why: ทำไมการตรวจนี้ยังไม่พิสูจน์ว่าข้อมูลเผยแพร่ทันจริง?**
เพราะเดือน t+1 จบก่อนวันที่ 15 ของ t+2 อยู่แล้วโดยสูตร การตรวจนี้ยืนยันว่าสูตรถูก แต่ FRED ไม่เก็บ vintage ว่าแต่ละวันเผยแพร่เมื่อไร เราจึงใช้ release cadence ของผู้เผยแพร่เป็นตัวแทน (H.10 เผยแพร่รายสัปดาห์) และเขียนเป็นข้อจำกัด

**What: `target_available_date` คืออะไร ใช้ทำอะไร?**
วันที่คำตอบของแถวนั้นเผยแพร่ = วันที่ 15 ของเดือน (เดือนเป้าหมาย + 2) ใช้คัดแถวฝึก: ณ วันพยากรณ์ใด ใช้ได้เฉพาะแถวที่ `target_available_date` ไม่เกินวันนั้น

**What: ผู้ตรวจอิสระตรวจข้อมูลอย่างไร?**
คำนวณ target และ feature ซ้ำจากข้อมูลดิบ (IMI, FRED) ทุกแถวที่สุ่ม ได้ผลต่างไม่เกิน 10⁻¹³ และตรวจ `*_max_date` ว่า feature แบบเต็มเดือนใช้ข้อมูลอยู่ในเดือน t+1 และแบบ cutoff24 ไม่มีวันเกินวันที่ 24

**Because: ข้อมูลรอบที่ 2 (ราคาปุ๋ยและนมโลก) ใช้อย่างไรให้ไม่รั่ว?**
สมมติว่าค่ารายเดือนของเดือน t+1 เผยแพร่ไม่เกินวันที่ 10 ของ t+2 (ปฏิทิน FAO ปี 2026 เผยแพร่วันที่ 2–9 และไฟล์ Pink Sheet ปรับปรุงวันที่ 2 ต.ค.) แต่วันเผยแพร่ย้อนหลังและการปรับแก้ค่าย้อนหลังยังไม่ยืนยัน
